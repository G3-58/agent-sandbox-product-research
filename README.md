# Agent Sandbox 竞品分析

面向企业内部 Agent 基础设施平台的产品研究，围绕 Sandbox 生命周期、开发者接入、成本治理与平台运营提出能力优先级建议。

## 研究范围

重点研究 E2B、Daytona、Modal、AWS AgentCore、阿里云、腾讯云、火山引擎七家厂商，并以 Vercel、Cloudflare、Northflank 和 Kubernetes Agent Sandbox 作为补充参照。

| 研究维度 | 关注的问题 |
| --- | --- |
| 隔离与安全默认值 | 不可信代码的执行边界、网络出口与凭证保护 |
| 创建与恢复 | 冷启动、预热池分配、快照恢复的口径差异 |
| 生命周期与状态 | 暂停、恢复、持久化、会话时限及回收策略 |
| 开发者接入 | SDK 兼容范围、镜像模板与迁移成本 |
| 计费与成本 | 存活时长、实际 CPU、内存和空闲资源的计费差异 |
| 平台治理 | 身份、网关、团队配额、审计、观测及成本归属 |

## 核心判断

1. 隔离技术并未完全同构，企业平台更需要明确安全默认值和可验证的运行边界。
2. E2B SDK 的兼容生态在扩展，但接口兼容不等于快照、存储、网关和治理能力可以无修改迁移。
3. 对高空闲占比的 Agent，计费口径和回收策略可能比计算资源标价更影响实际成本；内存与存储仍需单独核算。
4. 企业内部平台的差异化应落在接入门槛、运行可靠性、AI 网关和平台运营，而不只是启动速度。

这些是基于公开资料形成的产品判断，不是市场份额统计或性能实测结论。论据、限制与出处见完整报告。

## 面向内部平台的能力建议

| 阶段 | 建议重点 |
| --- | --- |
| P0 | 核心 SDK 兼容、安全默认值、创建与恢复、预热池及分级回收 |
| P1 | 模型与工具网关的边界、身份凭证、团队配额、会话观测、成本归属 |
| P2 | 镜像模板库、分场景接入文档和自助支持 |

衡量效果时优先关注：新团队接入耗时、创建成功率、创建/恢复 P99、单任务平均成本、空闲资源占比和安全事件。

## 方法与边界

- 本项目是个人产品研究，不是 Sandbox 实现或生产部署项目，也不是任何厂商的官方材料。
- 资料来自公开文档、产品页和定价页；厂商公布的时延不直接作为同条件性能排名。
- 价格是带日期的参考快照，未含流量、存储、套餐、税费和折扣；不同厂商的 GB/GiB 与 CPU 单位不强行混用。
- 保留原稿的研究框架和产品建议；发布时补充了官方来源、口径说明，以及对不完整或过强表述的修订记录。
- 未包含任职公司内部文档、用户数据、凭证或非公开架构。
